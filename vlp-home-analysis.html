Should home pins include unclaimed shops?

The practical question is not “can we remove them?” It is whether the coverage loss is small enough, and the map becomes clear enough, to justify removing them.

There are two different policies

The word “internet shop” is ambiguous in the current VLP model. The choice changes the empty-city risk materially.

Candidate A

Claimed-only

Keep: internet_shop + sku_less_internet_shop

Remove: unclaimed_shop

  • 149/1,244 cities empty (12.0%).
  • 3,059/463,899 requests empty (0.66%).
  • No empty cities among the 129 cities with at least 500 requests.
Candidate B

Strict internet-only

Keep: internet_shop

Remove: unclaimed and SKU-less registered shops

  • 240/1,244 cities empty (19.3%).
  • 7,146/463,899 requests empty (1.54%).
  • One ≥500-request city becomes empty; none ≥1,000.

Unclaimed shops are noisy, but not unused

The same seven-day home window contained substantial interaction with unclaimed shops. Removing them could improve relevance while also removing a real local-discovery path.

Unclaimed shops generated about 73% of home shop-profile clicks. Final/CTA clicks were 2,482 unclaimed, 416 internet, and 152 SKU-less.

Interpretation: the case for filtering is pin overload, not “unclaimed shops have no value.” A holdout is needed to see whether claimed shops absorb that demand.

Questions answered before implementation

Does the filter need to run in the query or only in serialization?

In the query. Post-filtering old search responses makes page 1 empty in roughly 22% of requests for claimed-only and 62% for strict filtering. For maps, post-filtering leaves mixed clusters counting shops that are no longer allowed.

Will the search page become much shorter?

No. Query-level filtering refills the page with retained shops. In the city-center size-54 replay, weighted result count fell about 4.2% for claimed-only and 6.3% for strict filtering. The map is where the larger reduction appears.

Are major cities at risk?

Not with claimed-only in this sample: no city with at least 500 home requests became empty. Strict filtering produced one empty ≥500-request city and no empty ≥1,000-request city.

What is still uncertain?

Map responses are viewport-specific and are not stored as city-level result logs. The clustering numbers are a live request replay, not a census of every city. Clicks also measure current behavior, not what retained shops would receive after a rollout.

Smallest safe next step

Run claimed-only as the first holdout.Keep both registered shop types; remove only unclaimed shops from home search and home clustering.
Measure the trade-off.Track viewport shop count, visible markers, empty responses, shop-profile clicks, CTA clicks, and page-1 empties.
Use strict filtering only if the holdout still shows overload.Strict filtering has nearly twice the empty-city rate of claimed-only and removes SKU-less engagement too.
